## 一、固件总体架构 (Software Architecture)

系统固件采用**分层模块化设计（BSP 驱动层 + 服务算法层 + 应用状态机层）**，基于轻量级非阻塞时间片轮询（Time-slice Cooperative Scheduler）或 SysTick 节拍驱动，避免复杂的 RTOS 内存开销，确保在 8KB SRAM 下高稳定运行。

```
┌────────────────────────────────────────────────────────────────────────┐
│                   应用层 (Application State Machine)                   │
│   - 正常监测态 (NORMAL)       - 火警报警态 (ALARM_SMOKE)                │
│   - 高温报警态 (ALARM_TEMP)   - 一键消音态 (MUTED)                     │
│   - 设备自检态 (SELF_TEST)    - 低功耗休眠态 (STANDBY)                 │
├────────────────────────────────────────────────────────────────────────┤
│                       服务与算法层 (Service & Algorithm)               │
│   - 烟雾浓度 ADC 滑动均值滤波 (16次均值)                                 │
│   - 迟滞回差报警判决算法 (Hysteresis 5% Deadband)                      │
│   - 按键软件消抖与单击/长按检测状态机 (20ms 滤波)                         │
│   - OLED 页面调度器与动态点阵字库渲染                                    │
├────────────────────────────────────────────────────────────────────────┤
│                       板级支持包 (BSP Hardware Drivers)                │
│   - bsp_sht30.c: I2C 数字温湿度传感器驱动 (带 CRC8 校验)                │
│   - bsp_smoke.c: ADC 连续采样 + EXTI 比较器中断                        │
│   - bsp_oled.c: SSD1306 128x64 单色点阵驱动                            │
│   - bsp_buzzer.c: TIM2 PWM 2.7kHz 脉冲频率控制                         │
│   - bsp_led.c: 绿/红双色指示灯 PWM 呼吸与急促快闪控制                  │
│   - bsp_key.c: EXTI / 轮询按键中断                                     │
├────────────────────────────────────────────────────────────────────────┤
│                   微控制器硬件层 (STM32G030 Peripherals)               │
│   - SysTick, TIM2 (PWM), ADC1 (PA0), I2C1 (PB8/PB9), GPIOA/GPIOB       │
└────────────────────────────────────────────────────────────────────────┘
```

## 二、关键外设时序与数据采集规范

### 2.1 SHT30 数字温湿度采集
1. **通信参数**：
   - 接口：I2C1（SCL: `PB8`, SDA: `PB9`）；
   - 通信频率：100 kHz（标准模式）；
   - 设备 I2C 地址：`0x44`（ADDR 引脚接地）。
2. **采集策略**：
   - 每 **1000 ms (1Hz)** 发送单次测量命令 `0x2C06`（高重复性，带时钟拉伸禁用）；
   - 延时 15ms 后读取 6 字节数据（`Temp_MSB`, `Temp_LSB`, `Temp_CRC`, `Humi_MSB`, `Humi_LSB`, `Humi_CRC`）；
   - 执行 CRC-8 校验公式（多项式 $0x31$，初始值 $0xFF$），若校验失败则保留上一次有效读数，连续 3 次失败触发传感器故障标志。
3. **物理量转换公式**：
   $$\text{Temperature (℃)} = -45 + 175 \times \frac{S_{RH}}{2^{16} - 1}$$
   $$\text{Humidity (\%RH)} = 100 \times \frac{S_T}{2^{16} - 1}$$

### 2.2 MQ-2 烟雾传感器采集与标定
1. **采样模式**：
   - 通道：ADC1 通道 0（引脚 `PA0`）；
   - 分辨率：12 位（0 ~ 4095），参考电压 $V_{REF} = 3.3\text{V}$；
   - 采样周期：每 **100 ms (10Hz)** 采集一次，每 16 次样本进入环形缓冲区（Ring Buffer）计算滑动均值，滤除电源与环境高频杂波。
2. **浓度与电压换算模型**：
   - 敏感体电阻 $R_s = \frac{V_{in} - V_{out}}{V_{out}} \times R_L$；
   - 结合洁净空气基准电阻 $R_0$，计算电阻比值 $\frac{R_s}{R_0}$，映射为烟雾浓度等效 PPM；
3. **双重报警机制**：
   - **快速响应**：若 `PA1 (SMOKE_DO)` 引脚产生下降沿外部中断（EXTI1），表示浓度瞬间越过硬件电位器设定的临界值，固件立即进入紧急响应模式；
   - **精准判决**：同时依据 ADC 连续采集值确认是否达到软件预设的报警阈值（默认 400 PPM），防止瞬时机械震动引起误触。

## 三、报警判决与回差（迟滞）算法

为了避免传感器读数在报警阈值边缘（如正好在 400 PPM 附近微小波动）导致蜂鸣器频繁起停鸣叫，固件严格采用**迟滞比较算法 (Hysteresis)**：

```
                    烟雾浓度 (PPM)
                         ▲
                         │
      报警触发阈值 ────┼─────────────┐ (触发警报: 蜂鸣器长鸣 + 红灯快闪)
      (400 PPM)          │             │
                         │             │     ┌─────── (浓度回落)
      消警复归阈值 ────┼─────────────┼─────┼─────────┐ (解除警报: 恢复绿灯)
      (360 PPM)          │             │     │         │
                         │             │     │         │
                         └─────────────┴─────┴─────────┴─────► 时间 (t)
```

1. **触发条件**：当前浓度值 $\ge 400\text{ PPM}$ 持续超过 500ms，系统转入 `STATE_ALARM_SMOKE`；
2. **解除条件**：当前浓度值降至 $\le 360\text{ PPM}$（留出 10% 的回差裕量）且持续 3 秒以上，系统才允许退出报警状态；
3. **高温预警**：当 SHT30 检测温度 $\ge 60.0℃$ 时，触发高温报警。

## 五、按键交互逻辑 (Human Machine Interface)

| 按键位号 | 动作 | 系统响应 |
| :--- | :--- | :--- |
| **KEY1 (消音/校准)** | **短按 (< 1.5s)** | 若当前处于报警状态，执行**一键消音**（蜂鸣器静音 120 秒，红灯持续闪烁提示）；若处于正常状态，点亮 OLED 屏幕背光。 |
| **KEY1 (消音/校准)** | **长按 (> 3.0s)** | 将当前环境读数校准为烟雾洁净空气基准值 $R_0$，并将标定参数保存至 MCU 内部 Flash 模拟 EEPROM。 |
| **KEY2 (翻页/自检)** | **短按 (< 1.5s)** | 手动切换 OLED 显示页面（实时主页 ➔ 历史极值页 ➔ 传感器原始参数页）。 |
| **KEY2 (翻页/自检)** | **长按 (> 2.0s)** | 启动**系统声光自检**：蜂鸣器鸣叫 1 秒，红绿 LED 轮流闪烁，OLED 显示全白屏幕检测坏点。 |

## 六、低功耗与异常自愈设计

1. **看门狗守护 (IWDG)**：
   - 启用独立看门狗，超时周期设为 2.0 秒；
   - 在主循环末尾喂狗，若 I2C 发生总线锁死或死循环，硬件自动复位重启系统。
2. **I2C 自动解挂 (Bus Lock Recovery)**：
   - 若 I2C 连续 3 次超时未应答，固件自动将 `PB8/PB9` 切换为 GPIO 输出模式，向 SCL 发送 9 个脉冲时钟，强制释放被 Slave 占用的 SDA 线，然后重新初始化 I2C 外设。
3. **断电参数记忆**：
   - 用户设定的报警阈值（如烟雾 300~1000 PPM、温度上限）保存在 MCU 最后一页 Flash（Page 31）中，断电不丢失。
