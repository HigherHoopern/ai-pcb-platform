SECTION 03 · FRONTEND CLOUD API ROUTING

三、 前端云 API 动态路由方案（零改动兼容现有 40+ 个后端接口）

目前前端 web/static/app.js 与 web/static/workbench_abc.js 使用相对路径 fetch('/api/...')。当您把前端单独打包成 macOS .dmg 或 Windows .exe 发给客户时，只需在 index.html 头部引入一段 40 行的 云端 API 路由与 License 鉴权拦截器（cloud_bridge.js），即可在不修改业务代码的前提下，将所有请求自动指向您的云服务器： 

// 文件：web/static/cloud_bridge.js
// 作用：在打包桌面客户端 (.dmg / .exe) 或独立部署前端时，自动将所有 /api/* 请求路由至云服务器并注入客户 License Key
(function () {
  // 1. 云服务器地址配置（可通过客户端登录页设置并持久化在 localStorage）
  const DEFAULT_CLOUD_SERVER = localStorage.getItem('xter_cloud_api_base') || 'https://pcb-api.yourdomain.com';
  const CLIENT_LICENSE_KEY   = localStorage.getItem('xter_client_license_key') || '';
  const IS_DESKTOP_APP       = Boolean(window.__TAURI__ || window.electronAPI || location.protocol === 'file:' || location.protocol === 'tauri:');

  window.XTER_CLOUD_CONFIG = {
    isDesktop: IS_DESKTOP_APP,
    apiBase: IS_DESKTOP_APP ? DEFAULT_CLOUD_SERVER.replace(/\/+$/, '') : '',
    setLicenseKey(key) {
      localStorage.setItem('xter_client_license_key', key.trim());
      location.reload();
    }
  };

  // 2. 全局重写 window.fetch：自动拼接云服务器域名并附加多租户 Authorization Header
  const rawFetch = window.fetch.bind(window);
  window.fetch = function (input, init = {}) {
    let url = typeof input === 'string' ? input : input.url;
    if (url.startsWith('/api/') && window.XTER_CLOUD_CONFIG.apiBase) {
      url = window.XTER_CLOUD_CONFIG.apiBase + url;
    }
    const headers = new Headers(init.headers || {});
    if (CLIENT_LICENSE_KEY) {
      headers.set('Authorization', `Bearer ${CLIENT_LICENSE_KEY}`);
    }
    return rawFetch(url, { ...init, headers });
  };
})();
SECTION 04 · MACOS (.DMG) & WINDOWS (.EXE) DESKTOP PACKAGING

四、 将前端打包为 macOS (.dmg/.app) 与 Windows (.exe) 安装包方案

🏆 推荐方案：Tauri 2.0 (Rust 原生壳) 首选商业交付方案
  • 安装包体积仅 5~8 MB（复用 macOS WebKit 与 Windows Edge WebView2，无需捆绑 150MB Chromium）。
  • 极高防逆向安全性：外壳与本地桥接逻辑直接由 Rust 编译为机器码二进制（Mach-O / PE），无法像 Electron 那样用 asar extract 一键解压出源码。
  • 一键产出全平台安装包：支持生成 .dmg、.app（macOS Apple Silicon & Intel）以及 .exe、.msi（Windows 10/11）。
备选方案：Electron + electron-builder 兼容性广
  • 自带固定版本 Chromium 内核，在老旧 Windows 7/10 机器上渲染表现完全一致。
  • 缺点是安装包体积约 120 MB ~ 160 MB，且必须配合 bytenode（V8 字节码编译）+ javascript-obfuscator 才能防止客户解包查看前端 JS。

SECTION 05 · HYBRID CLOUD & LOCAL DESKTOP TOOL BRIDGE

五、 关键痛点解决：后端在云上，如何让客户点击「用本机 KiCad / VS Code 打开」仍然生效？

当后端部署在云服务器时，云服务器显然无法直接执行 subprocess.Popen(['open', '-a', 'KiCad']) 打开客户电脑上的桌面软件。为此，我们针对网页版和桌面安装包版分别设计了无缝体验：

🌐 网页版用户点击「用 KiCad / VS Code 打开」时：

前端自动检测当前为浏览器环境，直接触发下载最新生成的 <Project>.kicad_pcb 或全套软硬件工程包 Full_Release_Bundle.zip，并在浏览器右上角弹出提示引导用户在本地打开。

💻 桌面客户端 (.dmg / .exe) 用户点击「用 KiCad / VS Code 打开」时：

Tauri 客户端内置一个仅 50 行代码的 Rust 本地同步函数 sync_and_open_local_tool(tool, cloud_zip_url)：自动将云端当前工程同步解压至客户本机的 ~/XterAI-Workspaces/<项目名>/ 目录，并直接调用客户电脑上的 KiCad 10 或 VS Code 打开！

SECTION 06 · FIVE-LAYER IP & CLOUD SECURITY HARDENING

六、 云端后端的 5 道防泄密与安全加固防线（上线必配）

1. Skill 知识库接口防爬取脱敏（保护 324 页蒸馏资产）

在 web/server.py 的 /api/skills/{skill_id} 接口中开启云端保护模式（CLOUD_PROTECT_SKILLS=1）：云端 AI 推理在服务器内存里读取完整的 SKILL.md / cheatsheet.md / patterns.md，但对前端 API 仅返回章节目录与 300 字摘要，防止同行通过接口爬走您的核心硬件知识库。

2. 多租户工作空间物理隔离（Multi-Tenant Workspace）

根据请求头中的 Authorization: Bearer <Token> 解析出唯一的 tenant_id，将云端工作空间路径映射为 workspaces/<tenant_id>/<project_name>/，确保 A 客户绝对无法访问或下载 B 客户的 PCB 与固件工程。

3. 宿主机 C99 状态机仿真安全沙箱（防恶意代码注入）

因为 /api/firmware/simulate 会编译并运行用户提交的 C99 代码，云端在编译前必须拦截 system()、popen()、fork()、exec*()、<unistd.h>、<sys/socket.h> 等危险调用，并在无外网权限、--memory=256m --cpus=0.5 的受限沙箱用户下执行。

4. 隐藏云端大模型地址与 API Key（内网通信）

在云端模式下，/api/config 接口自动隐藏您的 https://cloud-vllm-cluster.internal/v1 内网推理地址与 API Key；客户端无需配置大模型即可直接使用您云端的 Qwen3.8-27B 算力，按客户 License 配额扣减次数。

SECTION 07 · CLOUD SERVER DOCKER & NGINX DEPLOYMENT

七、 云服务器一键生产部署配置（Docker Compose + Nginx HTTPS） 

# 文件：docker-compose.cloud.yml（部署在您的私有云服务器上，客户不可见）
version: "3.9"
services:
  xter-ai-pcb-core:
    build:
      context: .
      dockerfile: Dockerfile.cloud
    container_name: xter-ai-pcb-core
    restart: always
    environment:
      - XTER_CLOUD_MODE=1
      - XTER_PROTECT_SKILLS=1
      - LLM_BASE_URL=https://cloud-vllm-cluster.internal/v1
      - LLM_MODEL=Qwen3.8-27B
    volumes:
      - ./workspaces:/app/workspaces
      - ./skills:/app/skills:ro
      - ./config:/app/config
    ports:
      - "127.0.0.1:8989:8989"
    deploy:
      resources:
        limits:
          cpus: "4.0"
          memory: 8G

  nginx-gateway:
    image: nginx:1.27-alpine
    container_name: xter-ai-pcb-gateway
    restart: always
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./deploy/nginx.conf:/etc/nginx/conf.d/default.conf:ro
      - ./deploy/certs:/etc/nginx/certs:ro
    depends_on:
      - xter-ai-pcb-core
